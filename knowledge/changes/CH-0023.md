# Why

`uv run pytest` takes about 4 minutes locally (245s for 938 tests on 2026-11-15) and slows every
iteration before a deploy. Measured with `--durations=0`, setup is ~145s of it, test bodies ~150s,
teardown ~19s. The fixtures in `tests/conftest.py` redo the same work for every test:

| Fixture work | Cost each time |
|---|---|
| `FakeEntra()` generates an RSA key | 55 ms |
| `make_config_dir` copies `config/`, `skills/` and `sample_sources/` | 140 ms |
| `load_snapshot` | 125 ms |
| `build_test_mcp_server` | 47 ms |
| uvicorn start + stop (`base_url`) | 290 ms |

An MCP test pays ~650 ms before it runs. Only 23 test files change the config they are given, and
only a few MCP test files change server state.

A refactor with no requirement delta: what the tests check does not change.

# Requirements

None changed.

# Design

All changes are in `tests/` except the dev dependency and CI.

- **One signing key per run.** `FakeEntra`'s default key comes from a key generated once per
  session. Tests that need a different key already pass their own (`key=RSAKeyPair.generate()` in
  `tests/auth/test_entra.py` and `tests/mcp/test_audit_events.py`).
- **A shared config snapshot for tests that don't change config.** The `store` fixture builds
  from the test's own copy only when the test asks for `config_dir` (by name, directly or through
  a fixture it requests). Otherwise it wraps one snapshot loaded once per session from one
  session-scoped config dir. The rule for test authors is: ask for `config_dir` when you change it.
  If the snapshot types turn out to be mutable, the shared one is guarded: a session-end check
  fails the run if it differs from a fresh load.
- **One MCP server per module, opt-in.** A module-scoped `shared_base_url` (with module-scoped
  key, store and port) for modules that change neither config nor server state, such as the persona
  matrix in `tests/mcp/test_rbac.py`. Modules with rate limits, block lists, connections or
  monkeypatched server state keep the per-test `base_url`.
- **A `slow` marker** (registered in `pyproject.toml`) on the tests that start a subprocess, read
  git history or run the multi-agent review loop: `tests/agent/test_goldfish.py`, the bundle lint
  in `tests/knowledge/test_bundle.py`, `tests/web/test_span_content.py`,
  `tests/ingest/test_remote_git.py`, the `sdlc-config diff` test in `tests/config/test_cli.py`.
  `uv run pytest -m "not slow"` is the inner loop. Plain `uv run pytest` and CI still run
  everything.
- **Parallel runs.** [workspace](../components/workspace.md): `pytest-xdist` in the dev group.
  `tests/support/db.py` names the test database per worker (`sdlc_test_<worker>`, plain
  `sdlc_test` without xdist), so `tests/db` can run in parallel. `uv run pytest -n auto` is
  documented as an option. [ci](../components/ci.md): the `test` job uses `-n auto` only if it is
  faster on the runner, measured in the PR. Locally, `-n 4` gained only 18% before the fixture
  work (245s to 201s), because each worker repeats ~10s of imports.
- **Stray telemetry.** A parallel run printed "Failed to export logs batch due to timeout": a test
  starts a real OTLP log exporter that times out at exit. Find it and keep exporters off in tests,
  as the conftest already does for the OTLP endpoint variables.

Pins before the work starts: the full suite passes today with 938 passed / 72 skipped locally
(no database) and with the database in CI. The same tests pass with the same counts after each
step.

Alternatives considered: running the MCP server in process (ASGI transport) instead of uvicorn.
Rejected, because the tests check auth and HTTP behaviour as deployed.
