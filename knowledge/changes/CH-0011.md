# Why

The user decided on 2026-11-11 to move all group mapping to Entra app roles.

Today, membership is the union of three things: Entra security groups, mapped by object ID in the
git-ignored `config/env/<env>/groups.yaml`; app roles; and direct members. Groups bring:
- a tenant file that every deploy must carry (CH-0010);
- group IDs that must never be committed;
- the token overage problem, along with the Graph fallback that CH-0005 removes;
- two equivalent paths to the same role, which version-03 P2 E1 had to prove equal.

App roles already cover everything groups do: assignment in Entra, the `roles` claim in the token,
and no overage.

# Requirements

The edits are applied when this record is approved, and each requirement goes back to `draft`:

- [FR-IDN-002](../requirements/functional/FR-IDN-002.md): "groups, app roles and direct members"
  becomes "app roles and direct members". The criteria about group IDs and the group map, and
  "each app-role persona resolves like its group twin", are removed. The `groups` claim is ignored
  if present.
- [FR-AUTHZ-005](../requirements/functional/FR-AUTHZ-005.md): `Source.access` accepts `teams`,
  `roles` or `everyone`. `groups` is removed, and a source that needs its own audience gets an app
  role instead.
- [FR-CFG-002](../requirements/functional/FR-CFG-002.md): `sdlc-config explain` accepts a persona,
  a set of app roles, or a direct-member alias. Groups are removed.
- [FR-IDN-003](../requirements/functional/FR-IDN-003.md): `config_explain(app_roles)`; the
  `groups` argument is removed.
- [NFR-PORT-001](../requirements/non-functional/NFR-PORT-001.md): "group IDs from the git-ignored
  group map" and "does not assume the `groups` claim" are removed. App-role values are config, not
  tenant data.
- [NFR-PRIV-003](../requirements/non-functional/NFR-PRIV-003.md): the git-ignored tenant files are
  `users.yaml` and `blocked.yaml`, and `groups.yaml` no longer exists. "No group ID" stays as a
  rule. Bundles no longer contain a group map.
- [NFR-SEC-004](../requirements/non-functional/NFR-SEC-004.md): the overage criterion is removed,
  because groups aren't read. Fail-closed on missing config and unreachable signing keys stays.

Supersedes CH-0005. With groups gone, removing the Graph fallback is part of this record, so
CH-0005 is set to `state: dropped` when this record is approved. CH-0005's NFR-PORT-001 edit (the
Graph host) is carried into this record.

# Design

- [sdlc_auth](../components/sdlc_auth.md): `Principal` no longer reads `groups`, `hasgroups` or
  the overage claim names. `groups.py` (with `GraphGroupResolver`) is deleted. Only `roles` and
  `oid` are used.
- [sdlc_config](../components/sdlc_config.md):
  - remove the `GroupMap` kind, the `groups.yaml` loading and the `group:` identity in bindings,
    team membership and `Source.access`;
  - a config file that still uses `group:` fails validation with a clear message;
  - `explain` and `personas.yaml` use app roles only;
  - bundles no longer include a group map;
  - the platform keys `groups.claim`, `overage_fallback`, `cache_ttl_seconds` and `graph_host` are
    removed.
- [config](../components/config.md):
  - the `group:` bindings in `roles.yaml` and the team files are removed, leaving the app-role
    bindings that exist today (`SDLC.User`, `SDLC.Admin`, `SDLC.<Team>.*`, renamed by CH-0009);
  - `groups.yaml.example` is deleted;
  - personas and the persona matrix drop their group twins;
  - team `metadata.owners`, today group aliases used only as labels, becomes the list of GitHub
    handles that CODEOWNERS uses (design D15, decided 2026-11-11). The schema accepts `@handle`
    values only. `tests/policy/test_codeowners.py` checks that each team file's CODEOWNERS rule
    names exactly the handles in its `owners`, and the comments in CODEOWNERS that mention group
    aliases are removed.
- [core_mcp](../components/core_mcp.md): `config_explain` takes app roles only, `whoami(explain)`
  no longer shows groups, the audit `group_source` field is removed, and the Graph wiring is
  deleted (from CH-0005).
- [scripts](../components/scripts.md): `entra_setup.ps1` stops creating groups and setting the
  groups claim; it manages app roles and assignments. The deploy script stops requiring
  `groups.yaml`.

Tenant (the user, confirmed per action):
- every user gets app-role assignments that match their current groups;
- the `groups` claim is turned off on the API app (`groupMembershipClaims`);
- the `GroupMember.Read.All` permission is removed;
- the groups can then be deleted.

Order with CH-0009: both change the Entra app roles, so they switch in the same tenant window.
CH-0009 renames the roles, and this record removes the groups.

Tests that pin today's behaviour before the work starts:
- `tests/policy/test_app_roles.py` (every app-role persona matches its group twin) proves that
  dropping the groups loses no access;
- `sdlc-config diff`, with groups removed, must show no change for app-role personas.

As built:
- `test_app_role_personas_match_group_personas` passed at c645f6e, the last commit with groups:
  every group persona had an app-role twin with equal access. After the change, HEAD's config
  with only its group parts stripped and the new config give the same teams, scoped roles,
  tools, skills, readable sources and ceilings for all 16 personas (checked with the new code).
  `sdlc-config diff` across this change cannot load the older config, which names groups.
- Personas are app-role only and use the new names (`payments-member`, `payments-approver`,
  `webapp-member`, `team-only`); the matrix lost 11 rows that became duplicates.
- The platform-infra test source keeps its own audience through a fixture-only platform role
  `infra-reader` bound to the app role `SDLC.Infra.Reader` (tests/support/config.py).
- The loader now requires a `config/env/<env>/` folder, so a mistyped `--env` still fails.
- `entra_setup.ps1` turns the `groups` claim off, assigns app roles to the test users (A:
  payments member, B: platform member, admin) and creates no groups. It removes nothing: the old
  app roles, assignments, `GroupMember.Read.All` and the groups are removed by hand
  (docs/guides/ENTRA_SETUP.md section 4).
- [compose](../components/compose.md) loses `ENTRA_GRAPH_CLIENT_SECRET`; [ci](../components/ci.md)
  no longer copies a group map example.
- Not done here (follow-up, infra_gcp): Terraform still creates the unused `groups-yaml` and
  `entra-graph-secret` secrets and the groups secret mount (used only without config bundles), so
  `gcp_deploy.ps1 -Step plan` still needs a `groups.yaml` file. The bundle (`-Step config`) no
  longer does.
- All seven rule sets mentioned groups and were edited, so they are back to `draft`.
