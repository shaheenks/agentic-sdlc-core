# Why

Phase WG.0 of `docs/plans/version-04.md`; design `docs/designs/gcp-native-hosting.md`, decision N13. The GCP stack
gets its own MCP server, `core_mcp_gcp`, with Google identity (CH-0021, CH-0022). Shared code goes in `libs/` and
is never copied between components, so the server body must be a library first. The identity-specific code in
`core_mcp` is small (token verifier in `server.py`, principal and policy lookup in `identity.py`); everything else
is identity-agnostic.

A refactor with no requirement delta: `core_mcp` behaves exactly as before.

# Requirements

None changed.

# Design

- New library `libs/sdlc_mcp` (workspace member, with its own component concept added in this change):
  - `IdentityAdapter` protocol: `verifier()` (a fastmcp `TokenVerifier`), `principal(claims) -> Principal`
    (user id, display name, email if any) and `memberships(principal) -> frozenset[str]` (the binding keys the
    resolver matches, e.g. `app_role:<value>`), plus `user_key(principal)` for `users.yaml`.
  - `build_server(adapter, settings)`: everything `server.py` builds today (tools, admin tools, artifacts and
    connections APIs, audit, telemetry, correlation, rate limits), taking identity only from the adapter.
  - The modules now in `mcp_servers/core_mcp/src/sdlc_core_mcp/` that are not identity-specific move here unchanged
    apart from imports.
- [core_mcp](../components/core_mcp.md): `EntraAdapter` (the current `EntraTokenVerifier`, `principal_from_claims`,
  app roles as memberships, `users.yaml` by `oid`) and an entry point calling `build_server(EntraAdapter(), ...)`.
  Image, settings, CLI (`reconcile_cli`) and URLs unchanged.
- [sdlc_auth](../components/sdlc_auth.md): `Principal` gains a neutral `user_id` (equal to `oid` for Entra); `oid`
  stays as an alias until the cutover. Resolver input is renamed from app roles to memberships inside the library,
  with `app_role:` keys produced by the Entra adapter, so config and its validation are unchanged.
- [workspace](../components/workspace.md): the new member in the uv workspace and its tests directory.
