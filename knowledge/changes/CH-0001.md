# Why

Three requirements are `live` but contain parts that only ran against fake APIs: Confluence, Jira and
Bitbucket sources, Atlassian and Data Center connections, and PDF OCR (inventory gap 6, version-03
P8). The traceability matrix reports them as live, so it can't show what P8 still has to check.
Splitting them gives each unchecked capability its own ID and `built` state, and its own exit
criterion: one recorded live run.

This change is specification only. No code changes.

# Requirements

- Adds [FR-KNOW-006](../requirements/functional/FR-KNOW-006.md) Atlassian and Bitbucket sources (`built`).
- Adds [FR-KNOW-007](../requirements/functional/FR-KNOW-007.md) OCR for scanned PDFs (`built`).
- Adds [FR-CONN-003](../requirements/functional/FR-CONN-003.md) Atlassian and Data Center connections (`built`).
- Modifies [FR-KNOW-001](../requirements/functional/FR-KNOW-001.md): the source types criterion
  becomes "local folder, git on GitHub (pinned SHA or tracked branch) and GCS; Atlassian and
  Bitbucket sources are FR-KNOW-006". The Notes line about gap 6 is removed.
- Modifies [FR-KNOW-004](../requirements/functional/FR-KNOW-004.md): the OCR criterion moves to
  FR-KNOW-007. The statement becomes "ingest PDF documents and cite page ranges". The Notes line
  about OCR is removed.
- Modifies [FR-CONN-002](../requirements/functional/FR-CONN-002.md): the Notes line about
  Atlassian and Data Center moves to FR-CONN-003. A new note says GitHub and Bitbucket Cloud are
  the providers this requirement covers.

The three modified requirements go back to `status: draft` and lose their `verified` entry.

# Design

Only the trace changes:

- [ingest_loaders](../components/ingest_loaders.md): `satisfies` gains FR-KNOW-006
  (`confluence.py`, `jira.py`, `atlassian.py`, Bitbucket remotes in `git.py`).
- [sdlc_connectors](../components/sdlc_connectors.md): `satisfies` gains FR-KNOW-006 (HTTP
  client, `jira_text`, `storage_format`) and FR-CONN-003 (Atlassian and Data Center providers).
- [ingest_bootstrap](../components/ingest_bootstrap.md): `satisfies` gains FR-KNOW-007 (OCR in
  `pdf.py`, with its cache). Its FR-KNOW-004 line drops "OCR only when the source opts in".
- [core_mcp](../components/core_mcp.md): `satisfies` gains FR-CONN-003 (`jira_get_issue`,
  `confluence_get_page`).
- [config](../components/config.md): `satisfies` gains FR-KNOW-006 and FR-CONN-003 (source types
  and the `atlassian` connection).

Each new requirement's `implementation` goes from `planned` to `built` when this record is done.
It is set to `planned` only so the draft passes the lint before the components list it.

Alternative considered: add a `live_checked` key to requirements. Rejected because it adds a
second status axis to every requirement, for a gap that affects three.
