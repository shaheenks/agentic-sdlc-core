# Why

When a method of the Agent Runtime app raises, Agent Runtime answers with "Reasoning Engine Execution failed"
followed by `Request Data: {...}`, the method's arguments. Every method takes `user_token`, so on 2026-11-13 a
refused `list_threads` (CH-0018's gateway denial) put the user's Entra access token in the error returned to the
caller and in the engine's error log. That breaks `NFR-PRIV-001` (no tokens in logs). The token was short-lived
and expired on its own.

A fix with no requirement delta.

# Requirements

None changed.

# Design

[user_agent](../components/user_agent.md), `agents/user_agent/runtime_app.py`:
- `list_threads` and `delete_thread` catch the expected refusals (`NotAuthenticated`, `LookupError`,
  `ValueError`) and return `{"error": {"code": ..., "message": ...}}`. `stream_query` does the same as a single
  yielded event before any session is created. Codes: `unauthenticated`, `not_found`, `invalid_argument`.
- Unexpected exceptions are caught too and returned as `internal` with a fixed message; the exception type (never
  its text or the arguments) goes to the agent's log.
- Messages are fixed strings and never include argument values.
- `scripts/agent_runtime_query.py` prints an error result plainly.

The platform may still log request bodies for other reasons; the method arguments carry only the token the call
needs and nothing is kept.

As built:
- `runtime_app.py`: the public methods wrap private ones (`_stream`, `_list_threads`, `_delete_thread`) and turn
  any exception into an error result via `_error`; unexpected errors log only their type.
- `scripts/agent_runtime_query.py` prints a refusal as `refused: <code>: <message>`.
- Tests: refusals return codes without raising; the token appears in no result and no log record; an unexpected
  error is `internal` and logs only its type.
