# Why

Since CH-0011, membership comes from app roles and users.yaml only, and the server never reads
`groups.yaml` or a Graph secret. Terraform still creates the `groups-yaml` secret from the
git-ignored file, mounts it into the MCP service and the ingest and reconcile jobs, and grants
three service accounts access to it. It also keeps the optional `entra-graph-secret`. So
`gcp_deploy.ps1 -Step plan` still needs a `groups.yaml` file whose content is never used. The user
has already removed the Entra groups.

This is a refactor with no requirement delta: nothing reads these secrets.

# Requirements

None changed.

# Design

- [infra_gcp](../components/infra_gcp.md):
  - `secrets.tf`: drop `groups-yaml` and `entra-graph-secret` from `secret_values`.
  - `variables.tf`: drop `groups_yaml_path` and `entra_graph_client_secret`; `dev.tfvars` and
    `staging.tfvars` drop `groups_yaml_path`.
  - `iam.tf`: drop both secrets from the `mcp`, `jobs` and `reconcile` service accounts.
  - `run.tf`: drop the `groups` volume and its mounts from the MCP service and the ingest and
    reconcile jobs, and the `ENTRA_GRAPH_CLIENT_SECRET` env entry. `main.tf`: drop
    `config_env_dir`.
  - `tests/infra/test_terraform.py` gains a check that no resource names `groups-yaml`,
    `entra-graph-secret` or `groups_yaml_path`.
- [scripts](../components/scripts.md): `gcp_deploy.ps1` stops setting
  `TF_VAR_entra_graph_client_secret` and stops requiring `config/env/<env>/groups.yaml` for `plan`.
- Docs: `docs/guides/GCP_DEPLOYMENT.md` and `config/env/dev/README.md`.

Effect of `plan` + `apply` on GCP dev: the two secrets and their versions are destroyed, their
IAM bindings removed, and new revisions of `sdlc-mcp-dev` and the ingest and reconcile jobs drop
the unused mount. With config bundles in use, nothing reads the mount today.
