# Why

Phase WN.3 of docs/designs/gcp-native-hosting.md. Adds the agent → MCP layer of the layered access model: deny by default at the
gateway, with a tool allowlist that config, not the console, decides.

# Requirements

- Adds [NFR-SEC-015](../requirements/non-functional/NFR-SEC-015.md) Layered access control on Google Cloud
  (`should`).

# Design

- [sdlc_config](../components/sdlc_config.md): `sdlc-config gateway-policy --env <env>` prints the MCP tool allowlist from `tools.yaml`
  (tools served by the server) as the gateway policy input.
- [infra_gcp](../components/infra_gcp.md): Terraform registers `user_agent` and `sdlc-mcp-native`
  (`google_agent_registry_service`, `_binding`), creates the gateway (`google_network_services_agent_gateway`) and
  the IAM Unified Access Policy that lets `user_agent`'s identity reach `sdlc-mcp-native`. The WN.0 spike found
  all of these in the provider (google 7.46.1).
- [scripts](../components/scripts.md): `gcp_deploy` passes the generated tool allowlist to Terraform (a
  variable), so the gateway policy and config stay one source.
- [ci](../components/ci.md): a check that the published allowlist equals the config catalog (no drift).
- Model Armor on prompts and tool responses: optional, off until evaluated.

As built:
- All in Terraform (`infra/gcp/gateway.tf`), no gcloud scripts: `google_network_services_agent_gateway`
  (Google-managed, `AGENT_TO_ANYWHERE`, MCP), `google_agent_registry_service` for `sdlc-mcp-native` (JSONRPC
  interface, `TOOL_SPEC`), `google_network_services_authz_extension` (IAP) with
  `google_network_security_authz_policy` on the gateway, and `google_iap_agent_registry_mcp_server_iam_member`
  (`roles/iap.egressor`, member `agent_runtime_principal`) with the CEL condition
  `iap.googleapis.com/mcp.toolName in [...]`, including `""` for the MCP handshake.
- The agent is not registered by hand: Agent Runtime agents appear in Agent Registry on their own.
- The allowlist and tool spec live in `infra/gcp/generated/gateway_policy.json`, written by
  `sdlc-config gateway-policy`; `tests/config/test_gateway_policy.py` fails when it differs from config, so CI
  catches drift through the test suite rather than a separate CI step.
- Rollout starts in DRY_RUN (`agent_gateway_enforce = false`: logged, fail open); enforcing is a variable change.
- `deploy_agent_runtime.py` attaches the engine to the gateway (`agent_gateway_config`) from
  `terraform output agent_gateway`; `--no-gateway` rolls back.
- Still to check live (WN.0 item): the gateway passes `Authorization` and `X-Serverless-Authorization` to the
  MCP server unchanged.
