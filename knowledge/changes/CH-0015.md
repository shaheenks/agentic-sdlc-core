# Why

Phase WN.3 of docs/designs/gcp-native-hosting.md. Adds the agent → MCP layer of the layered access model: deny by default at the
gateway, with a tool allowlist that config, not the console, decides.

# Requirements

- Adds [NFR-SEC-015](../requirements/non-functional/NFR-SEC-015.md) Layered access control on Google Cloud
  (`should`).

# Design

- [sdlc_config](../components/sdlc_config.md): `sdlc-config gateway-policy --env <env>` prints the MCP tool allowlist from `tools.yaml`
  (tools served by the server) as the gateway policy input.
- [scripts](../components/scripts.md): `scripts/agent_registry.sh` and `.ps1` register `user_agent` (Agent Runtime resource) and
  `sdlc-mcp-native` (MCP URL, tools), and apply the gateway policy. gcloud, because Terraform support is not
  confirmed.
- [infra_gcp](../components/infra_gcp.md): the IAM Unified Access Policy that lets `user_agent`'s identity reach `sdlc-mcp-native`,
  if Terraform supports it; otherwise in the script.
- [ci](../components/ci.md): a check that the published allowlist equals the config catalog (no drift).
- Model Armor on prompts and tool responses: optional, off until evaluated.

- A tool missing from the allowlist is refused at the gateway, with a log entry.
- A principal other than `user_agent` cannot reach `sdlc-mcp-native` through the gateway.
- `sdlc-config gateway-policy` output equals the `tools.yaml` catalog (test).
