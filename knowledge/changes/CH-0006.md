# Why

The traceability matrix lists `compose`, `scripts` and `workspace` with no verification. It also
lists `infra_gcp` as verified by `.github/workflows/ci.yml`, a workflow file rather than a test.
`user_agent`'s only test needs a real Entra token, Gemini and a running MCP server, so it never
runs offline or in CI. Together these components back several `must` requirements, including
NFR-SEC-006 (calls are made as the user) and NFR-SEC-010 (least privilege). The specification
claims verification that doesn't exist. This fix adds the tests. It changes no behaviour and no
requirement.

`scripts` is covered by CH-0007 (tests for `okf_bundle.py`). Its PowerShell scripts stay manual.

# Requirements

None changed: this is a fix to the trace, not to the specification.

# Design

The new tests are offline. They parse files or build objects and need no Docker, network or
secrets (NFR-MAINT-003).

- [compose](../components/compose.md), in `tests/infra/test_compose.py`, reading `docker-compose.yml`:
  - `user-agent` and `ui-copilotkit` have no `env_file` and no database variable (`POSTGRES_*`,
    `PG*`, `DATABASE_URL`). Only `core-mcp`, `migrate` and `ingest` get them (NFR-SEC-010).
  - Public hosts come from `SDLC_APP_HOST`, `SDLC_MCP_HOST` and `MCP_PUBLIC_URL` variables, and
    `localhost` appears only as a default value (NFR-PORT-002).
  - An OTLP endpoint is set for `core-mcp` and `user-agent` (NFR-OBS-001).
- [workspace](../components/workspace.md), in `tests/infra/test_workspace.py`, reading `pyproject.toml`:
  - Every `pyproject.toml` under `libs/`, `ingest/`, `mcp_servers/` and `agents/` is a workspace
    member, and every member has a `[tool.uv.sources]` entry (NFR-MAINT-001).
  - No member imports another member's `src` by path.
- [user_agent](../components/user_agent.md), in `tests/agent/test_user_agent.py`:
  - Import `agents/user_agent/agent.py` with the model stubbed.
  - Check that the MCP toolset uses `agent_header_provider`.
  - With a fake ADK context that carries a user token and a conversation id, the headers carry
    exactly that bearer token and that id, and nothing else (NFR-SEC-006, NFR-REL-002).
  - With no user token, no `Authorization` header is sent (no service-token fallback).
- [infra_gcp](../components/infra_gcp.md), in `tests/infra/test_terraform.py`, parsing
  `infra/gcp/*.tf` with `python-hcl2`, a new dev dependency:
  - Only the `mcp` service account has a grant on the artifact bucket (NFR-SEC-010).
  - The artifact bucket's lifecycle age comes from the retention variable (NFR-PRIV-004).
  - Scheduler jobs exist for ingest and reconcile (FR-KNOW-005, FR-IDN-004).
  - No Cloud Run service puts a secret value in a plain env var; secrets are references
    (NFR-SEC-007).

  `ci.yml` is replaced in `verified_by` by `tests/infra/test_terraform.py`. CI keeps
  `terraform validate`.

  Alternative considered: regex checks without a new dependency. Rejected because they break on
  formatting changes.

Each component's `verified_by` lists its new test file. Before writing the user_agent and Terraform
tests, read the code each claim depends on, so a test pins what the code does today. If a check
fails, that is a defect and gets its own fix record, not an edit to the test.
