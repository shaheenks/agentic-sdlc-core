# Why

Enforcing the gateway (CH-0015, `agent_gateway_enforce = true`) on 2026-11-13 broke every call. With
`AGENT_TO_ANYWHERE` egress, all of the agent's outbound traffic goes through the gateway, and IAP denied the
agent's fetch of Entra's signing keys as `unregisteredEndpoint`. Token verification then failed closed
("invalid or expired token"). The gateway behaved as designed; the registry was incomplete. Dev is back in
DRY_RUN.

The DRY_RUN audit log (30 hours, every `AuthorizeUser` decision) shows four destinations; only the MCP server is
registered:

| Destination | Purpose |
|---|---|
| `https://sdlc-mcp-native-…run.app/mcp` | MCP tools (registered, CH-0015) |
| `https://login.microsoftonline.com/<tenant>/discovery/v2.0/keys` | Entra signing keys (token verification) |
| `https://aiplatform.mtls.googleapis.com` | Gemini (`SDLC_MODEL_LOCATION=global`) |
| `https://asia-southeast1-aiplatform.mtls.googleapis.com` | Agent Runtime sessions (the engine's region) |

A fix with no requirement delta: it makes the agent → MCP layer of `NFR-SEC-015` enforceable as specified.

# Requirements

None changed.

# Design

[infra_gcp](../components/infra_gcp.md), `infra/gcp/gateway.tf`:
- A local map `agent_egress` of the three destinations above, each a `google_agent_registry_service` with
  `endpoint_spec { type = "NO_SPEC" }` and an `HTTP_JSON` interface (Google's documented form for external
  endpoints). Same gate as the rest: `local.gateway_on`.
- The Entra URL is built from `var.entra_authority_host` and `var.entra_tenant_id` (passed from `.env` by
  `gcp_deploy.ps1`), so no tenant id is committed. The regional host comes from `var.region`.
- One `google_iap_agent_registry_endpoint_iam_member` per destination: `roles/iap.egressor` for
  `var.agent_runtime_principal` (V1 policy, matching the MCP grant). No condition: these are not MCP servers.
- No wildcard host and no unregistered-endpoint rule: Google warns that a wildcard bypasses egress governance,
  and V1 has no unregistered rule anyway.
- Platform hosts Google lists that the agent does not use today (logging, telemetry, trace, monitoring, Secret
  Manager) are left out; the DRY_RUN check below shows if one appears.

Open point: Google does not document how a request URL is matched to an endpoint (host, or URL prefix). The
endpoints use the host (Google APIs) or the exact path seen in the logs (Entra). The DRY_RUN check confirms the
match before enforcing; if a request still shows `unregisteredEndpoint`, the URL is adjusted.

As built:
- `infra/gcp/gateway.tf`: `local.agent_egress` (`entra-signing-keys`, `vertex-ai-global`, `vertex-ai-regional`),
  `google_agent_registry_service.agent_egress` (`NO_SPEC`, `HTTP_JSON`) and
  `google_iap_agent_registry_endpoint_iam_member.agent_egress` (`roles/iap.egressor`, one per endpoint).
- Endpoint URLs are the Google API hosts and the exact Entra keys path; whether the gateway matches by host or by
  prefix is confirmed in DRY_RUN before enforcing (GCP_DEPLOYMENT rollout step 4).
- Tests: endpoints gated and granted one by one, no wildcard, and no GUID in any `.tf` or `.tfvars` file.
