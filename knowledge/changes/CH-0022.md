# Why

Phase WG.2; design decisions N7, N11, N12 and N13. With the server library (CH-0020) and the Google adapter
(CH-0021), the GCP stack gets its own MCP server and the agent on Agent Runtime switches to Google identity. The
Entra stack (`sdlc-app`, `core_mcp`, oauth2-proxy with Entra) is not touched.

# Requirements

Applied when this record is approved; each goes back to `draft`:

- [FR-IDN-005](../requirements/functional/FR-IDN-005.md): on the GCP stack a workflow authenticates with its own
  Google service account (an ID token for the OAuth client audience).
- [FR-ART-001](../requirements/functional/FR-ART-001.md): the owner is the token's user id (`oid` or `sub`), never
  a tool argument.
- [NFR-SEC-006](../requirements/non-functional/NFR-SEC-006.md): on the GCP stack the forwarded token is the Google
  ID token and the session user is `sub`.
- [NFR-SEC-010](../requirements/non-functional/NFR-SEC-010.md): per-user access on the GCP stack is decided by the
  Google ID token; the `core_mcp_gcp` service account is the only caller of the Cloud Identity API.
- [NFR-PORT-003](../requirements/non-functional/NFR-PORT-003.md): compose is the local twin of each stack (default
  profile: Entra; `gcp` profile: Google).

# Design

- New component `mcp_servers/core_mcp_gcp` (component concept added in this change): `build_server(GoogleAdapter(),
  ...)`, its Dockerfile and image `core-mcp-gcp`. No server code of its own beyond the entry point.
- [infra_gcp](../components/infra_gcp.md): `sdlc-mcp-native` runs the `core-mcp-gcp` image with
  `SDLC_OAUTH_CLIENT_IDS`, `SDLC_ALLOWED_DOMAINS` and the group lookup settings instead of `ENTRA_*`; enable
  `cloudidentity.googleapis.com`; the Agent Gateway egress endpoint `entra-signing-keys` becomes
  `google-signing-keys` (`https://www.googleapis.com/oauth2/v3/certs`). `sdlc-mcp` (main) and `sdlc-app` stay on
  Entra.
- [user_agent](../components/user_agent.md), [sdlc_agent](../components/sdlc_agent.md): the runtime app uses the
  Google verifier (`sub` as the user id); the container agent behind `sdlc_web` keeps Entra.
- [db](../components/db.md), [sdlc_db](../components/sdlc_db.md): a migration lets the artifact owner be either
  shape (GUID or Google `sub`), and records which stack wrote audit rows; no data moves.
- [compose](../components/compose.md): profile `gcp` with `core-mcp-gcp` and oauth2-proxy on the Google provider in
  front of `sdlc_web` (Google verifier); the default profile is unchanged.
- [scripts](../components/scripts.md): `deploy_agent_runtime.py` sets the Google settings; `agent_runtime_query.py`
  and `mcp_whoami.py --idp google` get the user's ID token with an installed-app OAuth flow for the configured
  client; `gcp_deploy.ps1` builds and pushes the new image; guides gain the OAuth client and Groups Reader setup.
- [ci](../components/ci.md): builds the `core-mcp-gcp` image; tests run for both adapters.
- Added while building: [core_mcp_gcp](../components/core_mcp_gcp.md) (the new component's concept),
  [sdlc_mcp](../components/sdlc_mcp.md) (`serve` with an adapter builder; `idp` in audit records),
  [sdlc_web](../components/sdlc_web.md) (the stack's verifier, for the compose profile) and
  [sdlc_artifacts](../components/sdlc_artifacts.md) (the object key takes either user id).

As built:
- `mcp_servers/core_mcp_gcp`: `build_auth` (Google verifier: client IDs from `SDLC_OAUTH_CLIENT_IDS`, domains
  from `platform.yaml` `identity.google`, not from an environment variable, so the server's domains are only
  ever the declared ones; block list by `sub`; RFC 9728 metadata naming Google), `build_identity`
  (`GoogleAdapter` + `CloudIdentityGroups` in the configured mode) and `main`. `sdlc_mcp.server.serve` now takes
  an adapter or a builder that gets the startup snapshot. Missing client IDs or `identity.google` stop startup.
- Audit: `tool_call` and `auth_failure` records carry `idp` (`entra` / `google`): the record of which stack wrote
  them. Audit is the structured log, not a table, so there is no audit migration.
- Agent: `sdlc_agent.runtime_guard` gained `verifier_from_env` (`SDLC_IDENTITY_PROVIDER`, default `entra`, an
  unknown value stops startup) and `principal_of` (claims of either stack, by the validated issuer); both the
  runtime app and `sdlc_web` use them, so the compose profile runs the same container agent on Google identity.
  `deploy_agent_runtime.py --idp google` is the default (`entra` = rollback): the engine gets the client IDs
  from .env and `SDLC_ALLOWED_DOMAINS` from `platform.yaml`.
- Database: migration `009_owner_id_shapes.sql` widens the `owner_oid` check to a GUID or a `sub` of 1 to 64
  digits; `sdlc_db.normalize_oid` and `sdlc_artifacts.object_key` use the same pattern. Connections and the
  block list were already keyed by any user id (a hash of it), so they needed no change.
- Infra: `mcp_services` names each service's workload, image and identity; `sdlc-mcp-native` runs
  `core-mcp-gcp` as the new `sdlc-<env>-mcp-gcp` account (the same grants as `mcp`, added as separate resources
  so no existing address moves), gets `SDLC_OAUTH_CLIENT_IDS` (`var.google_oauth_client_ids`, from .env) and no
  `ENTRA_*`; the shared `mcp_env` lost `ENTRA_*` (now per stack in `mcp_identity_env`). Output
  `mcp_gcp_service_account` names the account to give Groups Reader (Admin console, not Terraform).
- Compose: profiles `gcp` (`core-mcp-gcp` on :8090, `user-agent-gcp`, `oauth2-proxy-gcp` with Google sign-in on
  :4190) and `gcp-tunnel` (the public proxy). The proxy passes the ID token as `Authorization: Bearer`, which the
  agent and the MCP routes already accept. The chat app is not in the profile: it stays on the Entra stack until
  the UI moves (CH-0016).
- Scripts: `google_id_token.py` (installed-app sign-in with PKCE for a Desktop OAuth client, whose id is also in
  `SDLC_OAUTH_CLIENT_IDS`), used by `agent_runtime_query.py` and `mcp_whoami.py --idp google`. Guide:
  `docs/guides/GCP_STACK.md`.
- CI: unchanged. It builds no images today (`gcp_deploy.ps1 -Step images` does), and the test job already runs
  both adapters' tests.
- Fix after the first dev apply (the native revision failed its startup probe): `platform.yaml` fills its Entra
  fields from `${ENTRA_*}`, which the GCP stack's server rightly does not get. [sdlc_config](../components/sdlc_config.md)'s
  loader now gives an unset `ENTRA_*` the inert dummy value when `SDLC_IDENTITY_PROVIDER=google` (set by
  `core_mcp_gcp` itself, Terraform and compose); every other variable is still required. The test fixture had
  always set `ENTRA_*`, so the tests now also load the config without them.
