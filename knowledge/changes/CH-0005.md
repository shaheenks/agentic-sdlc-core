# Why

When a token omits a user's groups because they have too many (overage), the MCP server can
look them up in Microsoft Graph. This fallback was switched off on 2026-11-07 (version-03 P2,
`groups.overage_fallback: none`), because app roles are never cut by overage. The code is still on
every request's identity path: `GraphGroupResolver`, a client secret, a token cache and an outbound
call to `graph.microsoft.com` (inventory gap 12). Code that is wired in but off can be switched on
by a config edit, and it keeps a secret and a Graph permission alive for nothing. FR-IDN-002
already specifies the current behaviour: overage yields no groups and app roles still apply.

# Requirements

- Modifies [NFR-PORT-001](../requirements/non-functional/NFR-PORT-001.md): "Login and Graph hosts
  come from `platform.yaml`" becomes "The login host comes from `platform.yaml`". The Graph host is
  only used by the fallback. NFR-PORT-001 goes back to `draft`.

Behaviour for users does not change. The overage criteria in FR-IDN-002 and NFR-SEC-004 stay
true and keep their tests.

# Design

- [sdlc_auth](../components/sdlc_auth.md): delete `GraphGroupResolver` and the `GroupResolver`
  protocol. `effective_group_ids(principal)` takes no resolver and returns the token groups with
  source `token`, or no groups with source `overage_unresolved`. `GroupSource` loses `graph`.
  `Principal.groups_overage` stays, because detecting overage is still needed to fail closed.
- [core_mcp](../components/core_mcp.md): delete `build_group_resolver`. Remove the
  `group_resolver` parameter from `PolicyMiddleware`, `artifacts_api`, `audit` and `identity`. The
  `group_source` audit field stays, with two possible values.
- [sdlc_config](../components/sdlc_config.md): remove `groups_overage_fallback`,
  `groups_cache_ttl_seconds` and `graph_host` from the platform model and loader. A
  `platform.yaml` that still has the keys fails validation as unknown keys, as FR-CFG-001 requires.
- [config](../components/config.md): remove `identity.graph_host`, `groups.overage_fallback` and
  `groups.cache_ttl_seconds` from `platform.yaml`.
- [compose](../components/compose.md): remove `ENTRA_GRAPH_CLIENT_SECRET` from the `core-mcp`
  environment. Also remove it from `.env.example`.
- [infra_gcp](../components/infra_gcp.md): remove the `entra_graph_client_secret` variable, the
  `entra-graph-secret` secret and its env mapping in `run.tf`. The user runs the plan and apply. The
  plan should show only the secret, its version and the env var destroyed.

Docs: `docs/guides/ENTRA_SETUP.md` drops step 4 (Graph client secret) and the `graph.microsoft.com`
egress row.

Tenant: the `GroupMember.Read.All` application permission and the Graph client secret on the API
app should be removed. That is an Entra change, which the user makes or confirms per action
(`az account show` first). It is not part of the code work.

Tests that pin today's behaviour before the work starts:
- `tests/auth/test_entra.py::test_effective_group_ids_sources`: its `graph` case is deleted, and
  the `token` and `overage_unresolved` cases stay.
- The overage persona tests in `tests/policy/test_app_roles.py` and `tests/mcp` must pass unchanged.

Dropped on 2026-11-11: superseded by CH-0011 (membership from app roles only), which removes the
Graph lookup together with the groups. The Terraform `entra-graph-secret` stays until a follow-up
cleans up infra/gcp.
