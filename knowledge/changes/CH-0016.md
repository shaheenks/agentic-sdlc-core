# Why

Phase WN.4 of docs/designs/gcp-native-hosting.md. IAP replaces oauth2-proxy for the native stack; the UI must still hand the agent the
user's Entra token, because per-user access stays with Entra app roles (decision N1).

# Requirements

- Modifies [FR-IDN-001](../requirements/functional/FR-IDN-001.md): in `native`, an unauthenticated browser
  request is sent to sign-in by IAP (Cloud Identity with Entra SSO); the Entra token the UI uses must belong to
  the IAP user. Back to `draft`.
- Modifies [FR-SURF-001](../requirements/functional/FR-SURF-001.md): the chat talks AG-UI to the agent locally,
  and to Agent Runtime in `native`, with the same cards. Back to `draft`.

# Design

- [copilotkit](../components/copilotkit.md):
  - `lib/identity.ts` verifies the IAP JWT (`X-Goog-IAP-JWT-Assertion`); MSAL.js gets the Entra token by silent
    SSO; the server refuses a request whose Entra user is not the IAP user.
  - `lib/runtime.ts` gains the `agent-runtime` backend: an AG-UI agent that calls `stream_query` with the UI
    service account and maps ADK events to AG-UI (text, tool calls, cards). `SDLC_AGENT_BACKEND=agui` stays the
    local default.
  - Threads from `list_threads`; `/connections/` and `/artifacts/` proxied to `sdlc-mcp-native` by route
    handlers (user's Entra token + the UI service account's ID token).
- [infra_gcp](../components/infra_gcp.md): `sdlc-ui-native` with direct IAP (`iap_enabled`), access for a Cloud Identity group;
  the UI service account gets Agent Runtime query on the engine and invoker on `sdlc-mcp-native`.
