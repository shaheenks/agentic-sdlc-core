# Why

Phase WN.4 of docs/designs/gcp-native-hosting.md. IAP replaces oauth2-proxy for the native stack; the UI must
still hand the agent the user's own token. Since 2026-11-14 that is a Google ID token for our OAuth client
(decision N7, CH-0020), not an Entra token; this record follows CH-0020 to CH-0022 and CH-0025. Users are Cloud
Identity accounts of the allowed domain, signed in through Entra federation (2026-11-15, the user).

Changed on 2026-11-15 before any code (the user's choice): the UI server gets the token with its own OAuth code
flow instead of Google Identity Services in the browser. With GIS the token would sit in browser JavaScript, the
CSP would open to `accounts.google.com`, silent renewal depends on FedCM, and artifact downloads (plain links)
could not carry it anyway.

# Requirements

- Modifies [FR-IDN-001](../requirements/functional/FR-IDN-001.md): in `native`, an unauthenticated browser
  request is sent to sign-in by IAP (Cloud Identity, Entra federation); the Google ID token the UI forwards must
  belong to the IAP user. Back to `draft`.
- Modifies [FR-SURF-001](../requirements/functional/FR-SURF-001.md): the chat talks AG-UI to the agent locally,
  and to Agent Runtime in `native`, with the same cards and threads. Back to `draft`.

# Design

- [copilotkit](../components/copilotkit.md):
  - `lib/identity.ts`: verifies the IAP JWT (`X-Goog-IAP-JWT-Assertion`: ES256 on IAP's keys, issuer
    `https://cloud.google.com/iap`, audience from `SDLC_IAP_AUDIENCE`) on every request, and the user's Google ID
    token with the agent's rules (one of our OAuth clients, verified email, allowed domain). A token whose `sub`
    is not the IAP user's is refused. The IAP JWT is never forwarded (its audience is IAP).
  - `lib/session.ts` and `/chat/auth/*`: the OAuth code flow for the Web client, with PKCE and state, `prompt=none`
    and the IAP user as `login_hint`, so after IAP it is silent (a consent prompt only if Google needs one). The
    ID and refresh tokens are kept in one cookie, encrypted (AES-256-GCM, key from Secret Manager), httpOnly,
    Secure, SameSite=Lax, bound to the IAP `sub`; the server renews the ID token before it expires. The token
    never reaches browser JavaScript; the CSP stays closed.
  - `lib/runtime.ts` gains the `agent-runtime` backend (`SDLC_AGENT_BACKEND`; `agui` stays the local default): an
    AG-UI agent that calls `stream_query` as the UI service account with the session's ID token and maps ADK
    events to AG-UI (text, tool calls, tool results, so the cards render as today). Refusals
    (`{"refusal": {code, message}}`): `unauthenticated` renews the session or sends the user to sign-in, the
    others show the message; nothing is logged with a token.
  - Route handlers in place of oauth2-proxy's upstreams (rewrites outside `/chat`): `/threads` (`list_threads`,
    `delete_thread`), `/me` (from the verified identity), `/connections/*` and `/artifacts/*` proxied to
    `sdlc-mcp-native` with the user's ID token (`Authorization`) and the UI service account's ID token
    (`X-Serverless-Authorization`). Opening a thread replays it from `get_thread`.
- [user_agent](../components/user_agent.md): the runtime app gains `get_thread(user_token, session_id)`: the
  caller's own conversation as AG-UI messages (user, assistant, tool), the same refusals.
- [infra_gcp](../components/infra_gcp.md): `sdlc-ui-native` (the `ui-copilotkit` image, `agent-runtime` backend)
  with direct IAP (`iap_enabled`) and `roles/iap.httpsResourceAccessor` for `var.iap_access_group` (dev:
  `sdlc-user@<domain>`, which mirrors `SDLC.User`); its own service account with Agent Runtime query
  (`roles/aiplatform.user`) and invoker on `sdlc-mcp-native`; secrets for the Web client secret and the cookie
  key; no public invoker.

As built:
- Identity (`lib/jwt.ts`, `lib/identity.ts`): JWT checks on Node's crypto (no new dependency): one algorithm per
  issuer, a known key id, issuer, audience and time; the IAP `sub`/`email` lose their `accounts.google.com:`
  prefix and must equal the ID token's.
- Sign-in (`lib/session.ts`, `lib/auth-routes.ts`): Google returns a refresh token only on a consented
  authorization, so the callback asks once more with `prompt=consent` when none came back (one click per
  session; afterwards renewal is silent, 5 minutes before expiry). Session and flow cookies are `__Host-`,
  8 hours and 10 minutes. Sign-out drops the session and IAP's login cookie.
- Requests (`lib/native.ts`): `resolveUser` before every user call; on the copilotkit route the verified token
  replaces anything in `x-forwarded-access-token`, so the runtime's existing allowlist forwards it.
- Agent Runtime (`lib/agent-runtime.ts`, `lib/gcp.ts`): `:streamQuery?alt=sse` and `:query` as the UI service
  account (metadata server); ADK events to AG-UI as ag_ui_adk does (tool results as JSON text, so the renderers
  are unchanged); history through `get_thread` (the runner now takes a loader).
- Thread names (user_agent): CopilotKit names threads itself, Agent Runtime names sessions itself, so
  `stream_query` takes `thread_id`, kept in server-owned state (`sdlc_thread_id`, which client state cannot set);
  `list_threads`, `get_thread` and `delete_thread` use it. This process stores nothing.
- Same-origin paths: Next.js cannot rewrite outside its `basePath`, so `native-entry.mjs` (plain JS, in the image,
  the native service's command) maps `/me`, `/threads`, `/connections/`, `/artifacts/`, `/oauth2/sign_out` onto
  `/chat/api/native/*` and `/` to `/chat/`; locally the image still runs `server.js` behind oauth2-proxy.
- Terraform (`infra/gcp/ui_native.tf`): `native_ui_enabled`, `iap_access_group` (dev: `sdlc-user@`), the
  engine parsed from `agent_runtime_principal`, the domains read from `platform.yaml`, `google_web_client_id` /
  `_secret` from .env, a generated cookie key; preconditions for each. The IAP audience is derived as
  `/projects/<n>/locations/<region>/services/sdlc-ui-native` (the guide says what to check if IAP sends another).
- Fix after the first dev rollout (2026-11-16): a member of every group could not sign in; no request reached
  the service. Direct IAP used the Google-managed OAuth client, which admits only accounts of the project's
  organisation, and the users are accounts of another Cloud Identity organisation. IAP now signs in with our
  own client (`sdlc-iap-web`, redirect `https://iap.googleapis.com/v1/oauth/clientIds/<id>:handleRedirect`):
  set by hand with `gcloud iap settings set` first, then as `google_iap_settings.ui_native` (client id and
  secret from .env, `login_hint` the allowed domain).
