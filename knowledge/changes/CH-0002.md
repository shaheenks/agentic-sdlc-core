# Why

Some acceptance criteria appear word for word, or nearly so, in two or three requirements. When
one copy is edited and the other isn't, the specification disagrees with itself. Every copy also
has to be reviewed again whenever the rule changes. Each criterion should be stated once, in the
requirement it belongs to most, and the others should link to it.

This change is specification only. No code changes.

# Requirements

| Criterion | Removed from | Kept in (unchanged) |
|---|---|---|
| A deny wins over any allow | [FR-AUTHZ-002](../requirements/functional/FR-AUTHZ-002.md) (third criterion keeps only the `unconstrained` part) | NFR-SEC-002 |
| Every catalog tool has persona-matrix rows | [FR-AUTHZ-001](../requirements/functional/FR-AUTHZ-001.md) | NFR-MAINT-002 |
| A new source has matrix `data_rows` and a CODEOWNERS rule | [FR-AUTHZ-005](../requirements/functional/FR-AUTHZ-005.md) | NFR-MAINT-002, NFR-MAINT-004 |
| Tool cards are built from results, never by the model; forged cards are dropped | [FR-SURF-002](../requirements/functional/FR-SURF-002.md) | NFR-SEC-009 (it covers the chat as well as A2A) |
| Rollback moves the `current` pointer | [NFR-REL-001](../requirements/non-functional/NFR-REL-001.md) | FR-CFG-003 |
| A token without groups (overage) yields no groups | [NFR-SEC-004](../requirements/non-functional/NFR-SEC-004.md) | FR-IDN-002 (it also says app roles still apply) |

Each modified requirement gets a Notes line that links to where the criterion now lives. The six
go back to `status: draft` and lose their `verified` entry. The requirements that keep the
criteria are not edited.

Not changed: NFR-PORT-001 and NFR-PRIV-003 both mention the git-ignored group map, but one says
"not in code" and the other "not in the repository". Those are different facts.

# Design

- [sdlc_auth](../components/sdlc_auth.md): its NFR-SEC-004 line "Fails closed on missing groups
  and unreachable signing keys" becomes "Fails closed when the signing keys cannot be reached".
  Missing groups are already described under its FR-IDN-002 line.

No other component's `# Requirements` line mentions a removed criterion. The tests that pin each
criterion don't move: `tests/policy/test_matrix.py`, `tests/policy/test_codeowners.py`,
`tests/policy/test_authorize.py`, `tests/agent/test_a2ui_cards.py`, `tests/web/test_a2a.py`,
`tests/config` and `tests/auth`.
