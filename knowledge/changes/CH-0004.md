# Why

Today every stored version counts toward the 50-artifact limit (`count_live` in `sdlc_db`). A user
who revises one design document 50 times can't save anything else. How versions should count was
left open in FR-ART-002 (inventory gap 8, version-03 F6).

Decided by the user on 2026-11-10: count documents and cap versions per document. The cap was
set to 10 at approval (2026-11-12).

# Requirements

- Modifies [FR-ART-001](../requirements/functional/FR-ART-001.md): "at most 1 MiB each and 50 per
  user" becomes "at most 1 MiB per version and 50 documents per user. A document counts once,
  however many versions it has".
- Modifies [FR-ART-002](../requirements/functional/FR-ART-002.md): adds the criterion "a document
  keeps at most 10 versions. Saving an 11th is refused and says to save it as a new document or
  delete it". The open decision in Notes is removed.

Both go back to `status: draft`.

# Design

- [sdlc_artifacts](../components/sdlc_artifacts.md): `limits.py` keeps `MAX_LIVE_PER_USER = 50`,
  now documented as documents, and adds `MAX_VERSIONS_PER_DOCUMENT = 10`.
- [sdlc_db](../components/sdlc_db.md): `count_live` becomes
  `SELECT count(DISTINCT document_id) ... WHERE expires_at > now()`, still under owner RLS. A new
  `count_versions(conn, document_id)` counts live versions of one document.
- [core_mcp](../components/core_mcp.md): in `save_artifact`:
  - A new document (no `replaces`) checks the document count.
  - A new version checks the version count of that document. It doesn't add a document, so it skips
    the document count.
  - Each refusal is audited as `artifact_change` with outcome `limit`, and the message says which
    limit was hit.
  - `list_artifacts` reports both limits.

Storage: the worst case per user grows from 50 MiB (50 versions of 1 MiB) to about 500 MiB (50 ×
10 × 1 MiB). Retention (NFR-PRIV-004, 7 days) still bounds it.

Expiry is unchanged: each version row keeps its own `expires_at`, so a document's old versions can
expire before its newest one.

No migration is needed: the count is computed, not stored.

As built: the refusal audit records also carry `limit: documents` or `limit: versions`.
`list_artifacts` returns `limit` (documents, as before) and `versions_per_document`. The chat's
Artifacts panel does not show the limit, so the UI is unchanged.
