# Why

Phase WN.2 of docs/designs/gcp-native-hosting.md. The agent runs today inside `sdlc_web` (adk web) on Cloud Run. On Agent Runtime there is
no `sdlc_web`, so the protections it applies (token check, session ownership, client-state sanitising) must
move with the agent.

# Requirements

- Modifies [NFR-PORT-003](../requirements/non-functional/NFR-PORT-003.md): adds "In the `native` environment the
  agent runs on Agent Runtime; local compose runs the same agent code in a container." Back to `draft`.

# Design

- [sdlc_agent](../components/sdlc_agent.md): `runtime_guard.py` holds the rules now in `sdlc_web`'s middleware: verify the Entra token,
  take `user_id` from its `oid`, refuse sessions of other users, drop client state keys `temp:`, `app:`, `user:`
  and `sdlc_`. [sdlc_web](../components/sdlc_web.md) imports them from there (no behaviour change locally).
- [user_agent](../components/user_agent.md): `agents/user_agent/runtime_app.py`, an Agent Runtime app around `root_agent` with
  `stream_query(message, session_id, user_token)` and `list_threads(user_token)`. It binds the token with
  `set_request_token`, so MCP calls carry it as today. Sessions: `VertexAiSessionService` on the engine.
- [sdlc_auth](../components/sdlc_auth.md): `agent_header_provider` adds `X-Serverless-Authorization` (an ID token for
  `SDLC_MCP_IAM_AUDIENCE`, from the agent identity) when that setting is present. Never a service token in
  `Authorization`.
- [scripts](../components/scripts.md): `scripts/deploy_agent_runtime.py` creates or updates the engine from a tagged build (git
  SHA); rollback redeploys an older tag. Agent identity is enabled.
- [infra_gcp](../components/infra_gcp.md): the agent identity gets `run.invoker` on `sdlc-mcp-native` (a new binding per engine).
- Not here: A2A from Agent Runtime and Gemini Enterprise import (W6).
