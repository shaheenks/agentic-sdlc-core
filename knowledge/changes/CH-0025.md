# Why

CH-0019 made the runtime app return refusals as results: `{"error": {"code": "unauthenticated", "message": ...}}`
(for `stream_query`, one event). On dev (2026-11-15, CH-0022 verification) an Entra token sent to the engine was
refused as designed, but the caller crashed: `google.genai` (`_api_client.py`, `async_request_streamed`) treats
every streamed chunk whose JSON starts with `{"error":` as a Google API error and passes `error.code` to
`APIError.raise_error_async`, which compares it with numbers (`400 <= "unauthenticated"`: `TypeError`). The
refusal never reaches the caller. `list_threads` and `delete_thread` are not streamed and show the refusal
correctly.

Every `stream_query` client meets this, including the UI on Agent Runtime (CH-0016). A key the library does not
reserve fixes it for all of them; making the code numeric instead would turn refusals back into exceptions,
which CH-0019 removed on purpose.

A fix with no requirement delta.

# Requirements

None changed.

# Design

[user_agent](../components/user_agent.md), `agents/user_agent/runtime_app.py`:
- `_error` returns `{"refusal": {"code": ..., "message": ...}}`; codes and fixed messages unchanged
  (`unauthenticated`, `not_found`, `invalid_argument`, `internal`). The same shape for all three operations, so a
  client reads one key.
- The module docstring and the CH-0019 notes in the concept describe the new key.

[scripts](../components/scripts.md), `scripts/agent_runtime_query.py`: prints `refused: <code>: <message>` from
`refusal`.

Not in this change: CH-0016 is still a draft; its text is updated to read `refusal` (no code exists for it yet).

As built:
- `runtime_app.py` `_error` returns `{"refusal": {code, message}}`; the docstring says why not `error`.
- `agent_runtime_query.py` prints `refused: <code>: <message>` from `refusal`, for streamed and plain results.
- Tests: the shared helper requires `refusal` and no top-level `error` for every refusal (all operations and
  codes, both stacks); a refused stream event's JSON does not start with `{"error":`.
