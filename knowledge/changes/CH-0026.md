# Why

On dev (2026-11-16) a user in `sdlc-user@` and `sdlc-webapp-member@` got only `signed-in` on the GCP stack:
documents answered 403 and the agent's `get_agent_context` was refused. The server's logs showed his two
memberships found (`memberships:lookup` 200), but `groups:lookup` for `sdlc-platform-member@<domain>` answered
403 on every request since the first rollout (2026-11-15), while the seven other groups resolved with the same
service account. `GoogleGroupLookup` treats any error as "no groups at all" for that request, so one group that
cannot be found removed every group from every Google user. Until now it went unnoticed because the other users
were also listed in `users.yaml`.

Cloud Identity answers `groups:lookup` with 403, not 404, for an address it cannot find (or may not show), so the
code's 404 branch ("no such group") never runs and a typo looks like a missing Groups Reader role.

Groups only ever add access (`blocked.yaml` is not group based), so failing one group closed (no roles from
it) is still fail-closed; dropping all groups adds no safety and turns one config mistake into an outage.

A fix with no requirement delta (FR-IDN-004 and the CH-0021 rules are unchanged: lookup errors are not cached).

# Requirements

None changed.

# Design

[sdlc_auth](../components/sdlc_auth.md), `libs/sdlc_auth/src/sdlc_auth/groups.py`:
- `direct` mode: each group is looked up on its own; a failed `groups:lookup` or `memberships:lookup` makes the
  user not a member of that group only, and the warning names the group and the HTTP status. The result is not
  cached when any group failed, so the next request asks again.
- `transitive` mode (one paged call): unchanged, an error still gives no groups (there is no per-group answer).
- No email or token in the log record; group emails are config, not secret (CH-0021).

[sdlc_config](../components/sdlc_config.md), `sdlc-config check-groups --env <env>`: resolves every `group:` in
the env's bindings and teams with `groups:lookup` as the caller's ADC (or the service account it runs as) and
lists each as found or not, exit 1 if any is not. Read-only. Added to the GCP_STACK guide's rollout steps.

As built:
- `groups.py`: `_direct` looks each group up through `_member_or_none` (a failure logs
  `group lookup failed for <group> (<why>)` and counts as not a member) and returns whether every lookup
  answered; `groups_of` caches only a complete answer. `check(groups)` returns `ok`, `NOT FOUND` (404) or
  `NOT RESOLVED (<why>)` per group. The 403 comment in `_group_name` says what 403 can mean.
- `cli.py`: `check-groups` (`--env`, `--config-dir`, `--dummy-env`) prints `group: <email> <outcome>` and
  `groups: n/m resolve`, exit 1 if any does not, with a hint on 403. ADC with `GOOGLE_CLOUD_QUOTA_PROJECT` as the
  billing project. `sdlc_config` now depends on `sdlc-auth` and `google-auth[requests]`.
- Guide `GCP_STACK.md` section 1, both concepts and `libs/sdlc_config/README.md`.
