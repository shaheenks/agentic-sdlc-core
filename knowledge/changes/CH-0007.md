# Why

The project now works from the knowledge bundle: change records, traceability and the lint gate
in CI. No requirement says what that tooling must guarantee, and `okf_bundle.py` has no tests, so
a regression in the lint would quietly pass every bundle. The lint also lets two weak spots
through: a `verified_by` path that isn't a test (`infra_gcp` → `ci.yml`), and a built requirement
whose criteria are still "to be defined" (FR-ACT-001).

# Requirements

- Adds [NFR-MAINT-005](../requirements/non-functional/NFR-MAINT-005.md) The specification is
  traced and checked (`should`).

# Design

- [scripts](../components/scripts.md), in `scripts/okf_bundle.py`:
  - **Testability:** the bundle root becomes a parameter (default: `knowledge/` under the repository
    root) so tests can lint a temporary bundle. The CLI is unchanged.
  - **New rule:** a `verified_by` path must contain a `tests` folder segment or be a file whose
    name starts with `test_` or contains `.test.` or `.spec.`. Anything else is an error that
    names the path.
  - **New rule:** a requirement with `implementation` `live`, `built` or `stub` and a status other
    than `deprecated` must not contain "to be defined" (any case) in its acceptance criteria.
  - `satisfies` gains NFR-MAINT-005, and `verified_by` gains `tests/knowledge`.
- [ci](../components/ci.md): the `knowledge` job is unchanged. A test in
  `tests/knowledge/test_bundle.py` runs the lint on the real bundle, so `uv run pytest` catches
  what CI catches. `satisfies` gains NFR-MAINT-005.
- Tests, in `tests/knowledge/test_okf_bundle.py`, build small bundles in `tmp_path`. Each lint rule
  gets a passing case and a failing case: frontmatter, requirements, components, coverage, change
  records, reserved files and the two new rules. There are also tests that `build` is
  deterministic and that `stale` detects hand edits to generated files.

Order: the new rules fail on today's bundle until CH-0006 has replaced `infra_gcp`'s `ci.yml`
entry and CH-0003 has deprecated FR-ACT-001. This record lands after both, or carries those two
edits itself.

`knowledge/conventions.md` gets the two new rules in its "Rules the lint enforces" list. That
edits a reviewed concept, so it goes back to `draft` for review.
