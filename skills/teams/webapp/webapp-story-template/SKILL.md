# Template: webapp user story

Use this outline for a user story of the webapp team. Keep the headings; leave a section out
only with a one-line reason.

1. **Story:** As a <type of user>, I want <goal> so that <reason>.
2. **Acceptance criteria:** numbered Given / When / Then scenarios, including at least one error
   or permission case (signed out, another user's item, invalid input).
3. **API touch points:** endpoints added or changed (method and path), and whether the data
   model changes (a migration is needed).
4. **UI touch points:** pages, components and forms affected; loading, empty and error states.
5. **Test notes:** backend tests and Playwright flows that prove the criteria.
6. **Out of scope:** what this story does not cover.
7. **Open questions.**
