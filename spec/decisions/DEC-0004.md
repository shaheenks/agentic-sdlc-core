# Context

The user decided on 2026-11-22 that the agents on Agent Runtime are built with Google ADK, using graph
workflows and the latest ADK features where they help. ADK 2.0 describes an application as a graph of nodes
(agents, tools, human input steps, code functions) connected by edges. Its scheduler runs the graph, persists
state, pauses for people and resumes later, even in another process.

# Options

## A. ADK 2.0 graph workflows as the workflow engine (accepted)

- For: durable execution, human input and resumption come with the framework; agents are nodes; Agent Runtime
  hosts it and keeps its sessions; no workflow engine of our own.
- Against: live streaming is not supported inside graph workflows; some third-party integrations may not work in a
  graph context; ADK 2.0 features such as dynamic workflows are still maturing.

## B. A separate workflow engine calling ADK agents per step

- Against: a second durable-execution system and its storage, which [DEC-0003](DEC-0003.md) rules out for now.

# Decision

**A**, accepted by the user on 2026-11-22. Each catalog workflow is an ADK graph workflow; code-based dynamic
workflows are used only where loops or branching do not fit a graph. ADK built-ins come first: Agent Runtime
Sessions for state, human input nodes for tasks, the A2A integration for the A2A router.

# Consequences

- The [Workflow Engine](../components/workflow-engine.md) and [Human Tasks](../components/human-tasks.md) are
  realised inside the ADK application, `interactive_agents/user_agent/`, not as separate services.
- Agent output is not live-streamed inside graph workflows; surfaces show node-level progress events. The user
  accepted step-by-step output.
- The ADK version is pinned per release and upgraded deliberately.
