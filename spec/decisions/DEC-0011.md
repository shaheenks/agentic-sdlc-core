# Context

Phase 2 of the implementation plan builds knowledge ingest and search on JSONL files built into the Knowledge
Search image. The specification leaves four things open:

- which sources can be read before the connectors (phase 4) exist;
- how a source's readers are declared, and whether reads also have a classification ceiling
  ([FR-AUTHZ-004](../requirements/functional/FR-AUTHZ-004.md));
- how entities and edges of the knowledge graph are found;
- which embedding model to use.

The user chose an option for each on 2026-11-24. This record writes the choices down.

# Options

## Sources

- **A. Git repositories and folders (chosen).** A repository is cloned at a pinned commit or a tracked branch,
  with a read token from Secret Manager for a private one. A folder is a path in the build checkout or a
  `gs://` prefix. Jira and Confluence come with the connectors.
- B. Folders only: simplest, but the team repositories the agents need wait until phase 4.
- C. Repositories only.

## Access to a source

- **A. Source ID only, no ceiling yet (chosen).** Each source has a classification label, carried on every
  record. A source is readable or not, and the filter attribute is the list of readable source IDs.
- B. Four levels (public, internal, confidential, restricted), with a ceiling per grant.
- C. Three levels.

Readers are declared the way tool groups are: a grant names `sources` and its `to` (everyone, teams or user
groups). One place declares every permission, the team-run intersection applies unchanged, and the permission
diff ([FR-CFG-002](../requirements/functional/FR-CFG-002.md)) covers data as well as tools.

## Knowledge graph

- A. Structural only: sources, files, sections and code symbols, with `contains`, `links_to` and `imports`
  edges; no model calls, repeatable.
- B. Gemini extraction only: domain concepts and their relations, extracted per file.
- **C. Both (chosen).** The structural graph always; Gemini extraction on top, switchable per run.

## Embeddings

- **A. `gemini-embedding-001` on Vertex AI (chosen)**, output reduced to 768 dimensions and normalised.
- B. `text-embedding-005`, 768 dimensions.

# Decision

**A, A, C and A**, chosen and accepted by the user on 2026-11-24.

- `config/sources.yaml` declares each source: `kind` (`git` or `folder`), its location, branch or commit,
  include and exclude patterns, a `classification` label and, for a private repository, the Secret Manager
  secret of its read token. Grants gain `sources`.
- The Access Policy adds the readable sources to the effective policy. In the user's own runs (chat) that is
  every source granted to them; in a team run, only sources also granted to that team or to everyone
  ([FR-KNOW-004](../requirements/functional/FR-KNOW-004.md)).
- user_agent_mcp takes a run's team from the `X-SDLC-Team` header of its declared caller (the agent runtime);
  a user who is not in that team is refused. The knowledge tools send the readable source IDs as the filter
  attribute; no tool argument changes them.
- Knowledge Search drops every record outside the filter before ranking, and refuses a query without a filter.
- Records: `chunks.jsonl` (text, location, embedding), `entities.jsonl`, `edges.jsonl` and `manifest.json` (the
  run's status per source and the embedding model). Every record has `source_id` and `classification`.
- Ingest is incremental by file content hash: unchanged files keep their chunks, embeddings and extracted
  entities from the previous output, and files that are gone are left out.
- Embeddings and extraction run on Vertex AI in the platform's region (`VERTEX_LOCATION`); the extraction
  model is a setting. Locally and in tests, a deterministic hash embedder and no extraction need no cloud access.

# Consequences

- [FR-AUTHZ-004](../requirements/functional/FR-AUTHZ-004.md)'s classification ceiling is deferred: the label
  is stored, so a ceiling can be added later without re-ingesting.
- Knowledge Search refuses vector and hybrid queries when the store's embedding model differs from its own,
  so a model change means re-ingesting.
- Gemini extraction costs model calls on each changed file and its output can vary between runs; the
  structural graph does not.
- The interactive confirmation of a team-scope change ([FR-KNOW-004](../requirements/functional/FR-KNOW-004.md))
  belongs to the agent and the workflow run; user_agent_mcp enforces whatever team its caller names.
