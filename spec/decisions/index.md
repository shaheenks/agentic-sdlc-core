# Decisions

* [DEC-0001: sdlc_ui sign-in: Identity-Aware Proxy plus an internal OAuth app](DEC-0001.md) - `accepted` - How sdlc_ui authenticates Cloud Identity users and obtains the user token its BFF forwards: IAP as the perimeter, an internal OAuth app for the user's tokens.
* [DEC-0002: One MCP server, user_agent_mcp, for every call made as a user](DEC-0002.md) - `accepted` - user_agent_mcp serves the interactive agents on Agent Runtime and, once enabled, coding harnesses such as Google Antigravity, Gemini CLI and Claude Code, with tool groups declared per surface.
* [DEC-0003: No operations database in the first release](DEC-0003.md) - `accepted` - The platform keeps its state in managed Google Cloud stores (buckets, Secret Manager, Agent Runtime Sessions, Cloud Logging) and defers an operations database.
* [DEC-0004: Agents and workflows on Google ADK 2.0 graph workflows, deployed to Agent Runtime](DEC-0004.md) - `accepted` - Agents are built with Google ADK; multi-step workflows are ADK 2.0 graph workflows run on Agent Runtime, using ADK features before custom code.
* [DEC-0005: Tool access enforced in the MCP servers, with shared code in libs/](DEC-0005.md) - `accepted` - user_agent_mcp (user calls) and event_agent_mcp (system identity) each authorize and audit every tool call, run downstream reads and writes and require approval before writes, using shared libraries under libs/; there is no separate tool service.
* [DEC-0006: User connection secrets in the artifact bucket, encrypted by the application](DEC-0006.md) - `accepted` - Users' PATs live, encrypted with a key from Secret Manager, under secrets/users/ of the artifact bucket, which user_agent_mcp reaches through a mount; all other secrets stay in Secret Manager and reach services as environment variables. To be reviewed later.
* [DEC-0007: event_agent_mcp: a standalone MCP server for event-triggered agents](DEC-0007.md) - `accepted` - Agents in scheduled and event-triggered runs call their own MCP server, event_agent_mcp, as the system identity; user_agent_mcp serves user tokens only. Both live under mcp_servers/.
* [DEC-0008: Hand-off from user_agent to the event-based agents through Jira and the product repository](DEC-0008.md) - `accepted` - user_agent records approved features and stories in Jira and opens the approved design specification as a pull request on the respective repository, both with the user's own connections; the merge starts ci_workflow_agent, which reads only Jira and the repository.
* [DEC-0009: Google account tokens identify the user on every surface; IAP enforces the perimeter only](DEC-0009.md) - `accepted` - sdlc_ui and Gemini Enterprise both identify the user with a Google account token, forwarded to the agents and user_agent_mcp; the IAP signed token only gates access to sdlc_ui.
