# Context

[DEC-0002](DEC-0002.md) made user_agent_mcp the MCP server for agents acting for users. Scheduled and
event-triggered runs act as the system identity, not as a user, and need tools too: from the same server or from
one of their own. Both servers live under `mcp_servers/`.

# Options

## A. One server for user and system calls

- For: one deployment.
- Against: one service holds both user resources and system connections; a defect in identity handling could
  let a system token reach a user's artifacts or PATs, or a user reach system connections.

## B. A standalone server for unattended runs (accepted)

- For: user_agent_mcp accepts only user tokens and event_agent_mcp only the system identity, so neither can touch
  the other's resources; each has its own service account and storage prefixes ([DEC-0006](DEC-0006.md)); the
  event server has no browser or MCP-client callers, so it can keep a smaller exposure.
- Against: a second deployable with the same verification, policy and audit path. That code is shared as
  libraries under `libs/`, not copied ([NFR-ARCH-003](../requirements/non-functional/NFR-ARCH-003.md)).

# Decision

**B**, set by the user on 2026-11-22.

- `mcp_servers/user_agent_mcp/`: user tokens only ([FR-AGT-003](../requirements/functional/FR-AGT-003.md)).
- `mcp_servers/event_agent_mcp/`: the system identity's token only ([FR-AGT-004](../requirements/functional/FR-AGT-004.md)),
  for scheduled as well as event-triggered runs, since both act as the system identity; scheduled runs count
  as event-triggered
  ([FR-IDN-004](../requirements/functional/FR-IDN-004.md)).
- DEC-0002 still holds for user calls: one server for the interactive agents and, once enabled, coding harnesses.
- There are always exactly these two MCP servers, classified by nature of usage, access pattern, capabilities
  and configuration; each agent deployment connects only to its own
  ([NFR-ARCH-006](../requirements/non-functional/NFR-ARCH-006.md)).

| | user_agent_mcp | event_agent_mcp |
|---|---|---|
| Usage | work for a signed-in user | unattended work from schedules and events |
| Callers | interactive agents (`interactive_agents/user_agent/`); coding harnesses (parked) | event-based agents (`event_based_agents/`) |
| Access | users' Google tokens | the event deployment's service-account tokens, internal ingress only |
| Capabilities | the user's artifacts, connections, knowledge scope, workflows, tasks | system connections, `artifacts/system/`, write-back downstream |
| Configuration | per-user grants, per-surface tool groups, encrypted per-user secrets in the bucket | system identity tool groups, PATs as environment variables from Secret Manager |


# Consequences

- [event_agent_mcp](../components/event-agent-mcp.md) is a new component; user_agent_mcp no longer serves the system identity.
- The ADK application picks the MCP server by the run's identity: the user's run gets user_agent_mcp with the
  user's token, an unattended run gets event_agent_mcp with a system identity token.
- The event agents, ci_workflow_agent and operations_agent, run in their own Agent Runtime deployment
  Its service account is the system identity: the agents get short-lived
  Google ID tokens from the runtime, and no key or token is stored. Event metadata is carried on every
  trace ([NFR-OBS-003](../requirements/non-functional/NFR-OBS-003.md)).
- event_agent_mcp receives traffic only from that deployment. System connection PATs reach it as
  environment variables from Secret Manager; it uses them to act on Jira, Confluence, Bitbucket and GitHub, and
  they are not expired or rotated.
- System connections ([FR-CONN-004](../requirements/functional/FR-CONN-004.md)) are reachable only from
  event_agent_mcp; their secrets reach it as environment variables from Secret Manager ([DEC-0006](DEC-0006.md)).
- Results of unattended runs go back to the downstream systems the workflow declares, for example a comment on
  the pull request that started the run ([FR-TRIG-003](../requirements/functional/FR-TRIG-003.md)). No user surface shows unattended runs.
