# Context

Every tool call must be checked in one place: list only allowed tools, authorize each call with its arguments,
run downstream reads and writes through [Connectors](../components/connectors.md), require approval before
writes, and audit everything. Two MCP servers already sit on that path:

- user_agent_mcp verifies the user token, scopes every action to the user and reads the configuration bucket while
  answering ([DEC-0002](DEC-0002.md)).
- event_agent_mcp does the same for the system identity ([DEC-0007](DEC-0007.md)).
- Knowledge requests are proxied by the MCP server to the knowledge search service with a filter attribute
  ([NFR-ARCH-004](../requirements/non-functional/NFR-ARCH-004.md)).

# Options

## A. A separate tool service behind the MCP servers

- For: one enforcement point for both identities.
- Against: a third service on every tool call, adding latency against
  [NFR-PERF-001](../requirements/non-functional/NFR-PERF-001.md) and a service to keep at 99.5%; the MCP servers
  must still verify tokens and scope storage themselves, so enforcement would be split, not single.

## B. Enforcement in the MCP servers, sharing the code (accepted)

- For: one hop per tool call; each server enforces policy for exactly one kind of identity; one copy of the code.
- Against: two deployments to release together when the policy library changes.

Shared libraries under `libs/`: token verification ([Identity](../components/identity.md)), policy evaluation
([Access Policy](../components/access-policy.md)), audit records, the tool registry with read/write classes,
and the connector adapters ([Connectors](../components/connectors.md)).

# Decision

**B**, accepted by the user on 2026-11-22.

# Consequences

- Tool authorization, downstream calls and audit are satisfied by user_agent_mcp and, for unattended runs, by
  event_agent_mcp.
- Approval before writes ([FR-HUM-005](../requirements/functional/FR-HUM-005.md)) is checked by whichever server
  runs the write.
- Both servers run the same version of the shared libraries; a release of one library releases both servers.
