# Context

user_agent works for one user, and that user's artifacts are visible to no one else
([FR-AUTHZ-008](../requirements/functional/FR-AUTHZ-008.md)). ci_workflow_agent works as the system identity and
never reads user resources ([DEC-0007](DEC-0007.md)). Yet the approved features, stories and design
specification have to reach ci_workflow_agent for implementation.

# Options

## A. A shared prefix in the artifact bucket that the system identity can read

- For: no dependency on a repository.
- Against: breaks per-user isolation; the system identity would read data a user produced without a reviewable
  record of what was handed over.

## B. Jira and a pull request in the product repository, merged by a person (accepted)

Approved features and stories go to Jira, and the approved design specification goes to the respective
repository as a pull request, both with the user's own connections; a person merges the pull request; the merge
event reaches ci_workflow_agent through the [Event Gateway](../components/event-gateway.md).

- For: keeps both identities apart; the merge is the approval gate and the audit record; matches the playbook's
  committed-artifact chain; people can read and change the artifact with ordinary tools.
- Against: needs a declared repository and path per workflow, and a user connection with write access to it.

## C. A queue or API inside the platform

- For: no repository needed.
- Against: a new store the platform does not have ([DEC-0003](DEC-0003.md)); the approval would not be visible
  where the code lives.

# Decision

**B**, accepted by the user on 2026-11-23; superseded by [DEC-0012](DEC-0012.md), accepted by the user on
2026-11-25: approved artifacts go through each team's control repository, and the design is no longer a pull
request on a product repository.

# Consequences

- Each team declares its Jira project, Confluence spaces and repositories with their design path. The Jira
  status **In Design** allows a design run and **In Development** a development run.
- The user needs connections with write access to Jira and to that repository ([FR-CONN-001](../requirements/functional/FR-CONN-001.md)).
- The event gateway subscribes to merges under the hand-off path ([FR-TRIG-004](../requirements/functional/FR-TRIG-004.md)).
