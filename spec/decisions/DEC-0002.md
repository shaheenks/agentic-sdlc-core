# Context

Two kinds of caller make MCP calls as a user:

- Agents on Agent Runtime acting for the signed-in user ([FR-AGT-003](../requirements/functional/FR-AGT-003.md)):
  artifacts, connections, the user's own identity.
- Coding harnesses such as Google Antigravity, Gemini CLI and Claude Code, connecting directly
  ([FR-SURF-006](../requirements/functional/FR-SURF-006.md), parked): list and start workflows, follow runs,
  answer tasks, search knowledge.

Both need a Google-issued user token verified, the user ID taken from it, every action scoped to that user and
authorized through the same Access Policy. They differ in which tools they need.

# Options

## A. A server per kind of caller

- For: each has a small surface; the agents' server could be kept off the public internet if Agent Runtime can
  reach a private service.
- Against: two implementations or deployments of the same security-critical path (token verification, user
  scoping, audit); two services to run toward 99.5% availability.

## B. One server, tool groups per surface (accepted)

user_agent_mcp serves both. Each surface, identified by the OAuth client of the user's token, sees only the tool
groups declared for it ([FR-AUTHZ-006](../requirements/functional/FR-AUTHZ-006.md)).

- For: one verification and scoping path, one audit trail, one service; adding a harness is configuration only.
- Against: the server is public, so its connection-management tools are reachable from the internet. Per-surface
  tool groups and the user-ID scoping are what protect them, and no tool ever handles a secret
  ([FR-CONN-005](../requirements/functional/FR-CONN-005.md)).

## C. One server, the same tools for everyone

- Against: harnesses would get artifact deletion and connection management they do not need; least privilege
  per surface is lost. Not pursued.

# Decision

**B**, accepted by the user on 2026-11-22.

# Consequences

- [user_agent_mcp](../components/user-agent-mcp.md) satisfies [FR-SURF-006](../requirements/functional/FR-SURF-006.md).
- Tool groups per surface are configuration, checked by the [Access Policy](../components/access-policy.md).
- Unattended runs use their own server, event_agent_mcp ([DEC-0007](DEC-0007.md)). These are the only two
  MCP servers, one per class of caller ([NFR-ARCH-006](../requirements/non-functional/NFR-ARCH-006.md)).
- The harness surface is parked, so for now user_agent_mcp serves the interactive agents only.
