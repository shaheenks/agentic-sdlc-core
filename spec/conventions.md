# Purpose

This directory is an [Open Knowledge Format 0.3](https://okf.md/spec/) bundle describing the platform:
what it is made of, what it must do and why. OKF fixes the file layout, the `type` key and a few
optional key families; the rest of this page is this project's own convention.

# Layout

| Path | Holds |
|---|---|
| `components/` | One concept per logical component of the platform |
| `requirements/functional/` | One concept per functional requirement |
| `requirements/non-functional/` | One concept per non-functional requirement |
| `decisions/` | One record per design decision, `DEC-<nnnn>.md` |
| `traceability.md` | Generated: requirement to components, and gaps |
| `interfaces/`, `data/` | Planned: APIs and events, data model |

`index.md` and `log.md` are reserved OKF files. `log.md` is written by hand, newest first under
`## YYYY-MM-DD`. Every `index.md` below the root, `traceability.md` and the `nav` in `mkdocs.yml`
are generated by `uv run python tools/okf_bundle.py build`; do not edit them by hand. Run
`... lint` after every change; it checks the rules on this page.

# Links

OKF 0.3 resolves a link without a leading `/` from the directory of the file that contains it.
Links in this bundle are relative, so they work in editors and the repository browser too.
Concept IDs are bundle paths without `.md`, for example `/components/workflow-engine`.

# Concept types

| `type` | Use |
|---|---|
| `Component` | A logical part of the platform with one clear responsibility |
| `Functional Requirement` | Something the platform does for a user, team or operator |
| `Non-Functional Requirement` | A quality or constraint the platform must hold |
| `Decision` | A design choice between options, with its consequences |
| `Traceability Matrix` | The generated trace report |
| `Convention` | Rules for the bundle itself |

New types are added here when first used.

# Components

Components are **logical**: they name a responsibility, not a technology or a code folder. Where a
technology is already chosen it is recorded in the body under `# Realisation`; where it is not, it is
an open question. A component file is named in lowercase kebab-case.

Extension keys (OKF 0.3 reserves no `x-` keys, so they cannot collide with future versions):

| Key | Values | Meaning |
|---|---|---|
| `x-layer` | `experience`, `control`, `execution`, `capability`, `knowledge`, `records`, `platform` | Groups components in the index |
| `x-depends-on` | component concept IDs | Components this one calls or needs at runtime |
| `x-satisfies` | requirement concept IDs | Requirements this component helps to meet |
| `x-folder` | repository root folder, for example `mcp_servers/user_agent_mcp/` | Where the component's code lives, once decided; several logical components may share one deployable folder |

Body sections, in order: `# Purpose`, `# Responsibilities`, `# Out of scope`, `# Interfaces`,
`# Depends on`, `# Owns`, `# Requirements`, `# Realisation` (once a technology is chosen),
`# Open questions`. `x-depends-on` and `# Depends on` list the same components, and `x-satisfies`
and `# Requirements` the same requirements; the lint checks both. Every component satisfies at
least one requirement.

The trace is kept on the component side only. `traceability.md` turns it around per requirement.

# Requirements

- A requirement's file name is its ID: `FR-<AREA>-<nnn>.md` or `NFR-<AREA>-<nnn>.md`. Its concept ID
  is the path, for example `/requirements/functional/FR-WFL-004`; use the bare ID elsewhere.
- IDs are stable: never renamed or reused. Numbers are allocated in order within an area. A
  requirement that no longer applies gets `status: deprecated` (and `superseded_by` if replaced).
- Areas, functional: `SURF` surfaces, `IDN` identity, `TEAM` teams, `AUTHZ` authorization, `CFG`
  configuration, `WFL` workflows, `TRIG` triggers, `HUM` human tasks, `AGT` agent steps, `SKILL`
  skills, `CONN` connections, `KNOW` knowledge, `ART` artifacts, `MDL` models, `SDLC` SDLC flow (what the agents do at each stage). Non-functional:
  `HOST` hosting, `ARCH` architecture, `SEC` security, `PRIV` privacy, `AUD` auditability, `OBS`
  observability, `REL` reliability, `PERF` performance, `OPS` operability. A new area is added here
  and in `tools/okf_bundle.py` together.

| Key | Values | Meaning |
|---|---|---|
| `x-area` | an area code | Must match the ID |
| `x-priority` | `must`, `should`, `could` | How much the platform depends on it |
| `x-implementation` | `live`, `built`, `stub`, `planned`, `parked` | State of the code |

`status` is about the text (reviewed or not); `x-implementation` is about the code. A `live`,
`built` or `stub` requirement must be satisfied by at least one component.

Body:

```markdown
# Statement

One sentence: "The system shall ...".

# Acceptance criteria

- Observable, testable facts.

# Notes

Optional: open decisions, targets to be agreed, related requirements.
```

# Decisions

A decision record is `decisions/DEC-<nnnn>.md`, numbered in order and never renumbered. Its body has
`# Context`, `# Options` (one `##` per option, with what speaks for and against it), `# Decision`,
`# Consequences`, and optionally `# Open questions` and `# Citations`.

| Key | Values | Meaning |
|---|---|---|
| `x-state` | `proposed`, `accepted`, `rejected`, `superseded` | Where the decision is; only the user accepts or rejects, and the record says when |
| `x-affects` | component or requirement concept IDs | What the decision shapes |

Requirements and components that depend on a proposed decision link to it and say so.

# Citations

Claims taken from external documentation go under `# Citations` as numbered links,
`[1] [Title](https://...)`, as OKF recommends.

# Review states

| State | Frontmatter | Meaning |
|---|---|---|
| Draft | `status: draft` | Written, not yet reviewed |
| Reviewed | `status: stable` + a `verified` entry by `human:<id>` | A person has confirmed the text |
| Retired | `status: deprecated`, optionally `superseded_by` | Kept for history |

Only a person marks a concept `stable`. Editing a reviewed concept in substance sets it back to `draft`.
